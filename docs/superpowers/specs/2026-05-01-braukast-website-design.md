# Braukast Website — Design Spec

**Date:** 2026-05-01  
**Domain:** braukast.de  
**Repo:** https://github.com/Braucast/podcast.git  
**Deployment:** GitHub Pages (root of `main` branch)

---

## Goal

A single-page website for the Braukast podcast. No CMS, no framework. Displays all published episodes automatically from the podcast RSS feed. The site is intentionally minimal — the podcast is the product, the site just indexes it.

---

## Visual Design

**Style:** Minimal Dark  
**Background:** `#0f0f0f`  
**Text primary:** `#e8e8e8`  
**Text secondary:** `#3a3a3a`  
**Accent:** `#4ade80` (green) — used on episode numbers, "Anhören" links, and the tagline  
**Borders:** `#161616` / `#1a1a1a`  
**Font:** System stack (`-apple-system, 'Segoe UI', sans-serif`)

No external CSS frameworks. All styles inline or in a single `<style>` block.

---

## Page Structure

### Header
- Logo image (left) + "Braukast" wordmark
- Short tagline below the name (green) — hardcoded in `index.html`, pulled from the RSS `<description>` field by the GitHub Action and written into `episodes.json` as a top-level `"description"` key on first run
- Platform badges (right, wraps on mobile): Spotify, Apple Podcasts, RSS
  - Spotify: green badge linking to `https://open.spotify.com/show/1i8txBkDNEeDaKPsgbxToD`
  - Apple Podcasts: dark badge — URL to be added later
  - RSS: dark badge linking to `https://anchor.fm/s/10038620/podcast/rss`

### Episode List
- Section label: `ALLE FOLGEN` (small, spaced, dark)
- Each episode row:
  - Episode number (green, e.g. `#42`)
  - Title
  - Date (formatted as `24. April 2025`) + duration (e.g. `· 58 min`)
  - `Anhören ↗` link (green, right-aligned) → Spotify episode URL
- Rows separated by a subtle `#161616` border

### Footer
- Single line: `© 2026 Braukast`

## Data Model

Episodes are stored in `episodes.json` at the repo root:

```json
[
  {
    "number": 42,
    "title": "Hopfenanbau in Bayern",
    "date": "2025-04-24",
    "duration": "58:12",  // normalized from itunes:duration (HH:MM:SS or MM:SS → display as "58 min" or "1h 12 min")
    "url": "https://open.spotify.com/episode/..."
  }
]
```

The `index.html` fetches `episodes.json` on load and renders the list. No server-side rendering.

---

## GitHub Action — `fetch-episodes.yml`

**Trigger:** `workflow_dispatch` only (manual, via GitHub UI)

**Steps:**
1. Fetch RSS from `https://anchor.fm/s/10038620/podcast/rss`
2. Parse XML with Python's `xml.etree.ElementTree`
3. Extract per episode: title, pubDate, duration (`itunes:duration`), episode link
4. For the Spotify episode URL: extract from `<spotify:episodeUri>` if present in the feed; fall back to the Anchor episode link (`<link>`)
5. Episode number: use `itunes:episode` from the feed if present; otherwise derive from position (oldest item in feed = `#1`, incrementing upward)
6. Write sorted (newest first) `episodes.json` to repo root
7. Commit and push `episodes.json` if changed — GitHub Pages picks it up automatically

**Runtime:** Ubuntu latest, Python 3.x, no extra dependencies (stdlib only)
